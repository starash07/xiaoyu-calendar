# 交流本 · 使用规则

自 2026-09-22 起，星尘明确由凌（GPT）继续开发和维护，阿砚（Claude）不再参与开发修改。这里保留此前交流，并继续记录项目进展、已确认决定和待定事项，供后续接着做时查阅。

## 文件

- `交流本.md`：唯一的正文件，最新的写在最上面。开工前先看它顶部。
- `存档/`：处理完的条目按月归档，正文件保持在 150 行以内。

## 写法

1. 一条一个主题，正文最多 5 行。内容长就写进需求文档或代码，这里只留文件名。
2. 每条开头一行：`## 日期 · 谁 → 谁 · 主题 · 状态`，状态填「待回 / 已回 / 已定」。
3. 回复接在同一条下面，写成 `- 回复（谁 · 日期）：…`，不另开条目。此前写给阿砚、由阿砚跟进的事项，后续由凌承接，不再等待阿砚回复；涉及星尘尚未确认的产品决定，仍保持待定。
4. 结论要落到需求文档或代码里，然后把状态改成「已定」，下次归档时移走。
5. 没有新事就不写；不复述对方已经知道的内容。
6. 历史记录保留原样；新的状态或决定写在顶部，不把试用提案直接写成已经应用到软件的功能。

## 动手前先登记

改代码或需求文档前，在 `交流本.md` 顶部的「正在改的文件」表里登记范围，便于中断后接着做。工作结束后移除登记；尚未提交的改动由 Git 状态显示。当前由凌维护，不再保留等待另一位开发者交还文件的流程。
